## C ↔ JS fidelity

No `rn2` in `parse`. `in_parse = true`, `command_count = 0`, `context.move = 1` (C `TRUE`), `flush_screen(1)`, `input_state = commandInp`.

`!num_pad || (foo = readchar()) == spkeys[NHKF_COUNT]`. The `readchar` runs only when number_pad is on. The count key defaults to `'n'` (110). Inside that arm, `input_state` is set back to `commandInp`, then `get_count(NULL, '\0', LARGEST_INT, &count, GC_NOFLAGS)`. `LARGEST_INT` is 32767 (`global.h:135`). `GC_NOFLAGS` is 0. `get_count` writes `cntbox.n` and returns the terminating key. That matches the pointer out-parameter.

`get_count` reads `nhgetch`, not `readchar`, so it does not run `readchar_done`. C's last `readchar` inside `get_count` sets `input_state = otherInp` (`cmd.c:5267–5271`). JS assigns `otherInp` after `get_count`. On the number_pad path where the first key is not the count prefix, `readchar` already set `otherInp` and the arm is skipped. That matches.

`last_command_count = command_count`. ESC (`spkeys[NHKF_ESC]`, default 27) clears the message window and both counts. `in_doagain` copies `last_command_count` back. The repeat / prevmsg / extcmd bind does the same. Those copies are identity: `last` was just stored from `command_count`, and ESC already returned through the first arm. C has that same order. The extcmd names are `repeat`, `prevmsg`, and `#` (`extcmdlist` for `do_repeat`, `doprev_message`, `doextcmd`). `cmdbind_get` returns that row, so `bind.txt` is `ef_funct`. The key is masked with `0xff`.

`multi` is the count, then decremented when non-zero. `cmd_key = foo`, message window cleared, `in_parse = false`, return `cmd_key`.

`rhack`: queue pop still runs only when the incoming key is 0 (the pre-existing gate). C pops even for `rhack(cmd_key)`. `allmain.c:530` is that call; `js/allmain.js` still uses `rhack(0)` and keeps run/search on their own loops. This commit did not add that caller. When the key is 0 and the queue is empty, `parse` runs. A 0 return with `cmdq_peek(CQ_CANNED)` `continue`s, which is `goto got_prefix_input`.

The abort is `!key || key === -1 || key === ESC`. ESC copies `sanity_check` onto `sanity_no_check` and does not ring. The other two ring `tty_nhbell`. Both call `reset_cmd_vars(true)`. C is `!key || key == (char)0377 || key == ESC`, then the same split. On this platform `(char)0377` is -1, and `readchar` returns `(char)sym`, so byte 255 comes back as -1. JS `readchar_core` returns `sym | 0` and maps EOF to ESC, so it does not return -1. A 255 from `readchar` does not take this arm. A -1 from `get_count`'s `nhgetch` does. `_repeat_search = false` is not in C `rhack`; `search_repeat_active` also requires `multi > 0`, which `reset_cmd_vars` clears.
